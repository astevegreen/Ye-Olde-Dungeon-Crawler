# Quest, Trigger & Ending Mechanics

> Topic doc under [content-extensibility.md](content-extensibility.md) ([ARCHITECTURE.md](../../ARCHITECTURE.md) §3). Explanatory only — every binding rule about content integration lives on the guaranteed-read path (`ARCHITECTURE.md`'s §3 stub and `content-extensibility.md`'s core sections), never only here. Flag a conflict rather than resolving it here (§8.2).

## Generic Tile-Triggered Choice
`actions/movement.ts`: any tile whose `interactionHandlerId` matches a `manifest.choices` key becomes an interactive decision point, resolving at most once (a `<handlerId>_resolved` flag, set only once an option is actually chosen, so cancelling leaves it re-triggerable). An option marked `keepsOpen` doesn't resolve it, so a tile can offer several things to do in any order (cotw's two grotto hearths: rest, and read or listen); such an option carries a `predicate` so it can't be taken twice. Supports `ChoiceDefinition.resolvedStates` (`{ flag, message }` or `{ when, message }` with a predicate, e.g. both of a hearth's flags), allowing content to preserve persistent resolution messages (e.g. purified/desecrated altars) without hardcoded engine branches. The previous `altar_tyr` branch in `movement.ts` was deleted and folded into this generic mechanism.

## NPC Choices
`NpcConfig.choiceId` (`entities/npc.ts`, set from `ScriptedVaultNpc.choiceId`, saved with the NPC): talking to the NPC opens that `manifest.choices` entry instead of its greeting, at no turn cost (`actions/movement.ts`). Unlike a tile choice it never resolves, so the NPC can be spoken to again; its options gate themselves with predicates (e.g. `minFaction`) and their own flags, and a disabled option shows its `disabledReason`. cotw's Ivalda (`ironClans.ts`) is one.

## Monsters That Stand Aside
`Entity.setFaction` lets content move an entity between sides. A `neutral` monster takes no action (`MonsterAI.decideAction` waits), since the default target is the player whatever the faction. The player cannot bump-attack it; walking into it trades places with it (`actions/movement.ts`), so one standing in a one-tile corridor never walls it off. The hero's companion (a `player`-faction monster) trades places the same way. cotw's Iron Clans hook sets the Haugbui neutral for a hero the clans trust, and hostile again once one is hurt or trust is lost.

## Fixed Tile Placements & Acquisition Configuration
`types/manifest.ts`, `dungeonArc.ts`: `manifest.fixedTilePlacements` (`FixedTilePlacement[]`) declares floor-specific tile placement patterns (e.g. `'middle_room_center'`) gated by optional choice prerequisites (`requiresChoiceId`), replacing hardcoded campaign floor-3 altar stamps. Similarly, `manifest.runeOfReturn.acquisition` (`{ floor, vaultId }`) specifies where the Rune of Return appears, removing `FLOOR5_RUNE_VAULT_ID` from the engine.

## Scripted Vault Placements
`types/manifest.ts`'s `ScriptedVaultPlacement`, `manifest.scriptedVaultPlacements`, `dungeonArc.ts`: `{ floor, vaultId, npcs? }` forces a vault onto a floor (the Rune of Return acquisition vault wins if both name the same floor) and fills the vault's `N` layout markers with the declared NPCs, in row-major order. Three generic `VaultBlueprint` fields support it:
- `legend` maps extra layout symbols to tile types resolved through the tile registry, so a vault can stamp the pack's own `tiles` (an interactive altar with an `interactionHandlerId`) without the engine naming them. A legend entry wins over the built-in symbols.
- `scriptedOnly` keeps a vault out of the random vault pass: it appears only where a manifest forces it.
- The monster side of the same idea is `MonsterDefinition.placedOnly`: such a monster is never drawn at random (floor population, vault fill, wandering spawns), so it appears only where content places it, typically as a scripted vault's `minibossId`. cotw's Sun-Chariot Warden is placed this way, once, in the Chariot Forge on floor 25, and so are its other bosses and minibosses (Gálmr on 5, Svartr on 36, Gloom-Tarr in the Bile-Sump on 44, Víðnir on 45, Sköll in the Marrow Ossuary on 47, Níðhögg in the lair): `placedOnly` is the only rule that keeps a monster out of random draws (the engine no longer guesses from an id containing "boss").
- The generator tracks whether the forced vault was actually stamped (`DungeonResult.forcedVaultPlaced`) rather than inferring it from chest spawns, so chest-less vaults don't burn every retry. Player spawn and exit stairs go in ordinary rooms, never a vault, so a forced vault's authored center is never overwritten.

Worked example: the CotW Siphon Altar (`src/content/cotw/hostageRitual.ts`) composes a scripted placement (vault, altar tile via `legend`, four captive NPCs), a tile-triggered choice (the altar), a timed event (the ritual countdown), and two action hooks — a `MovementAction` pre-hook that rescues a captive on bump instead of opening dialogue, and a `'*'` post-hook that starts the countdown, settles captives per the chosen altar option, and sacrifices the remainder on expiry; on its first run there it also seats the villagers the prologue's raid took in their captives' places (same ids, so every flag holds). All three routes funnel into one outcome function. No engine code names any part of it.

## Standing-Driven Town Prices & Temple Gates
`manifest.merchantPricing` (`{ faction, tiers: { minStanding?, maxStanding?, multiplier }[] }`) multiplies merchant buy prices by the first tier matching the player's standing with `faction`; absent, prices are flat. `TownServicesDefinition` carries the temple's gates: `templeStandingFaction` (default `'temple_standing'`; negative standing refuses service), `templeRefusalMessage`, and optional `corruptionRefusalThreshold` / `corruptionSurchargeThreshold` / `corruptionSurchargeMultiplier` against `Actor.corruptionScore`. The cleanse is never refused (Q50): a hero the gates would turn away pays double for it, as one wearing a `templeShunned` item does, and the two don't stack. `templeOfferings` (`TempleOfferingsDefinition`) names the families, by alignment, the temple takes from the pack as offerings (`TempleService.makeOffering`: identified items only, no coin, the offering's renown milestone and `standingDelta`; accepted at any standing, refused while a `templeShunned` item is worn), and `templeBlessings` (`TempleBlessingDefinition`) the blessings granted once each, free, at a piety threshold (renown in `pietyCategory`, default `piety`): `freeHealing`, `hallowItem` (one plain carried item of the listed categories gains a family at the tier of the deepest floor reached) or `maxHpPercent` (`Player.maxHpPercentBonus`); refused below 0 standing or while a `templeShunned` item is worn, and remembered as the world flag `temple_blessing:<id>`. cotw (`town.ts`, Q9/Q49/Q50): negative families for 5 piety and +1 standing each; Eir's Mercy at 30 (free healing), Thor's Hallowing at 60 (Holy), Baldr's Grace at 100 (+10% max HP). `smiths` (`SmithDefinition`, `economy/smith.ts`) gives a merchant a Forge list: `SmithService.upgrade` raises a carried or worn item's +N one step for `stepPricesCp[level]`, up to the list's length (identified, unbound items of `categories`; a step is a dungeon +N's worth, +2 attack on a weapon, +1 defense otherwise), and an optional `masterwork` takes one item straight to `toLevel`, free, once, while its `predicate` holds and its `flag` is unset. cotw (Q10/Q47, Q29/Q48): Gunther's steps to +3 at 250 / 750 / 2,000 CP, and Ivalda's masterwork to +5 once the Iron Clans trust the hero and she works beside him (it replaces her old +2 Attack and shares its flag). `TempleService` reads these from `manifest.town.services` whenever it is handed the engine. `monsterLore` (`MonsterLoreDefinition`, `economy/lore.ts`) has the sage sell monster lore, each priced `baseCp + perFloorCp ×` the creature's home floor (`minFloor`): `LoreService.study` raises a known creature one bestiary rank without a kill (`CompendiumManager.raiseKnowledge`; the bought rank is saved as the record's optional `studiedTier`, which the kill count can't lower), and `LoreService.rumor` reveals an unmet creature the hero picks from a list of home floors (`revealByRumor`, the Seen rank). cotw (Q11/Q60/Q61): Study 50 + 10 × floor, Rumors 500 + 50 × floor.

## Victory Portal & Town Return
`movement.ts`, `deathResolver.ts`, `types/manifest.ts`: `manifest.quest.victoryPortalTileId` declares the tile stamped at the boss's defeat coordinate, handled by the generic `'quest_victory_portal'` handler in `movement.ts` (triggering victory and teleporting to `manifest.quest.townReturnPosition` or `manifest.town.playerSpawn`), replacing hardcoded `gateway_valhalla` and `{ x: 25, y: 23 }` coordinates. Stepping in ends the run with whichever ending `checkVictoryEligible` finds eligible on that floor (the legacy single ending when the quest declares none). `quest.relicDropMessage` and `quest.victoryPortalMessage` are logged at the boss's death only when set. Tile presentation is decoupled via generic `TileDefinition` properties (`visual: 'portal'`, `landmarkLabel`).

## Turn-Limited World Events
`types/manifest.ts`'s `TimedEventDefinition`, `manifest.timedEvents`: a `startFlag`/`turnLimit`/`resolvedFlag`/`expireConsequences` countdown, ticked once per player turn by a `'timed-events-tick'` environmental update (`GameEngine.tickTimedEvents`, alongside surfaces/substances/spawns) — independent of any modal, so it keeps running while the player does anything else. Lets a climactic choice feel time-pressured (fight through resistance before it's too late) rather than a calm, simulation-paused dialogue menu, without needing a bespoke per-campaign timer. Its clock counts turns, and resting advances turns outside the action pipeline, so the hero cannot rest while any countdown runs (`AutoRestManager.restRefusal`, which names a labelled one and its turns left; `getRunningTimedEvents` lists every running one): a rest would otherwise spend it unseen and let it expire on the next step. A countdown must be visible to be fair: an optional `label` makes the HUD draw it as a `[LABEL Nt]` badge (`quest/timedEvents.ts`'s `getTimedEventCountdowns`, which reads the `timed_event_started:<id>` flag and `timed_event_start:<id>` counter `tickTimedEvents` writes), and a `StoryChoiceTrigger`'s `progressStartMessage` is logged the moment its `progressStartFlag` starts one.

## Kill-Count-Gated Choice Unlocks
`StoryChoiceTrigger`, `manifest.storyChoiceTriggers`: unlocks a `ChoiceDefinition` once a monster (by `definitionId`) has been slain `killsRequired` times, read from `GameEngine.compendium`'s existing per-`definitionId` kill count (cross-floor-safe and already persisted — `DeathResolver` calls `compendium.recordKill` on every real death). Checked in `movement.ts` (real `GameEngine` access) rather than an `ActionHook`, whose `EngineContext` deliberately can't reach the compendium or open a choice modal (see [content-extensibility.md](content-extensibility.md)'s Injected Context section, "widen it deliberately" — this didn't need widening, since `movement.ts` already has full access). Triggers on *progress* rather than *location*, for encounters that span floors; a hand-placed encounter on one floor uses Scripted Vault Placements (above) instead. An optional `when` (a `Predicate` over world state) must also hold, for a beat that waits on more than a kill: cotw's Blood-Oath waits for the Sun-Chariot Warden's death *and* the Hearth-Tear in hand.

## Attribute-Threshold-Gated Choice Unlocks
`LevelMilestoneTrigger`, `manifest.levelMilestones`: unlocks a `ChoiceDefinition` once the hero reaches `level` (cotw: the Saga perks at 10, 20, 30, 40 and 50); an optional `when` predicate holds it until an earlier choice has set a flag, so a choice can ask a follow-up on the next move (cotw: Elementalist's element), checked before the attribute milestones below with the same idiom. `AttributeMilestoneTrigger`, `manifest.attributeMilestones`: unlocks a `ChoiceDefinition` once a player attribute (`strength`, `dexterity`, `constitution`, or `intelligence`) reaches `threshold`. Sibling of `StoryChoiceTrigger`: uses the same one-time `<id>_offered` world-flag idiom, persisted through existing `WorldState` flags. Checked every player move in `movement.ts` (matching `StoryChoiceTrigger`: the condition is progress, not location) rather than inside `Player.allocateAttribute`, preserving `allocateAttribute` as a pure, engine-independent mutator and preventing a choice modal from opening over the Character tab while points are being spent. Both kinds of progress choice are held while a prologue runs, and after it in town until its `aftermathFlag` is set (`isPrologueHoldingChoices`; cotw: Hallvard's last words), so a milestone a new hero is born past opens on their first move after that beat, not over it. Below ground the aftermath holds nothing, so a hero who walks past it is not held for good. cotw (`milestones.ts`, Q6/Q26, tracker 3.3) offers each attribute a perk choice at 20, 25 and 30, built from whichever `milestone_<attr>_<tier>` choices `choices.ts` holds (all three tiers, two perks each, Q52), and a starting attribute is capped at 16 (`MAX_ATTRIBUTE`), below the first tier, so a milestone is earned with a level's points, never rolled.

## "Driven Off" Boss Resolution
`BossFleeResolution`, `manifest.bossFleeResolutions`: converts sustained fleeing (the existing `fleeHealthPercent` mechanic already makes a monster flee below a HP threshold) into a concluded encounter — while the named monster is alive, on the active floor, and `aiState === 'fleeing'`, a turn counter accrues; once it reaches `fleeTurnsRequired`, `sealedFlag` is set once and the monster is removed from the floor (map and turn order), so the fight can't simply resume. An optional `portalTileId` is stamped where the monster stood, with `portalMessage` logged, so a driven-off boss can open its own way out (cotw: the path home).

Its counterpart for the kill is `QuestArcDefinition.bossSlainFlag`: `DeathResolver` sets it when `bossMonsterId` dies, so an objective or a `trackedMilestones` entry (both read flags only) can follow the slain branch as they follow `sealedFlag`.

## Multiple Named Endings
`QuestArcDefinition.endings`, `EndingDefinition`: generalizes the single flat `victoryDialogue`/`victoryEpitaph`/`championProclamation`/`victoryScoreBonus`/`relicItemId`/`victoryFloor` fields (which remain the sole, default `'default'`-id ending when `endings` is omitted — existing packs, including `warcraft`, are unaffected) into named, independently-conditioned endings, each gated by `relicItemId` (carried), `requiredFlag` (world-state flag set), and/or `requiredMonsterKillId` (compendium kill count ≥ 1). `GameStateManager.checkVictoryEligible(engine)` now returns the matching ending id (or `undefined`) instead of a boolean, checked in insertion order; `triggerVictory(engine, profileManager?, endingId?)` uses that ending's own text/bonus and reports the `endingId` to `onStateChanged`. Lets one boss encounter branch into different concluded sagas (e.g. slain vs. driven off) sharing the same fight. An ending may also carry `title` and `narrative` (paragraphs), which presentation shows on a narrative screen (`src/ui/endingDialog.ts`) before the score screen, and a `banner` for that score screen. cotw sets each ending's `victoryFloor` to 50, so the endings are taken through the portals on the boss floor.

## Prologue
`types/manifest.ts`'s `PrologueDefinition`, `manifest.prologue`, `quest/prologue.ts`: a short scene played on the town map before the run proper. `ProfileManager.createCharacter` begins it only when asked (its `prologue` option, which the composition root passes for a new hero; tests and the sim start in the plain town), via `beginPrologue`: the hero stands at `playerSpawn`, `startFlag` is set, the declared `monsters` (floor-1 strength, ids from `prologueMonsterId(index)`, already alert when `awake`) and `npcs` are placed, and `applyPrologueState` unlights the town (`dark`) and sets the hero's HP floor (`heroHpFloor`). Neither of those two is saved, so the deserializer calls `applyPrologueState` again after a load.

The engine only stages and undoes the scene; the pack's own hooks run it and decide when it is over, then call `concludePrologue(ctx, prologue, townLit)`: the prologue's monsters and NPCs still on the map leave, the town takes back its light, the HP floor lifts, `aftermathNpcs` take their places (the nearest free tile when theirs is taken), `endFlag` is set and `closingMessage` logged. `isPrologueRunning` reads the two flags. An optional `aftermathFlag`, set by the pack, marks the aftermath's own beat over (progress choices wait on it in town, above). While one runs the hero cannot rest (`AutoRestManager.restRefusal`, as during any timed event): the scene's clock counts turns, and a rest would spend them unseen. The F2 triage menu can end one too (`engine.diagnostics.endPrologue`, the engine's half only: the pack's own ending does not run), and a triage floor jump ends any first, so its HP floor never follows the hero down.

The HP floor is generic (`Entity.setHpFloor`): damage cannot take the entity below it, and `wasHeldAtHpFloor` records that a blow was held back, so a pack can turn a would-be death into a scripted outcome (cotw's hero is struck down rather than slain).

## Story Presentation
The character menu's Story tab (ADR-0011) reads only manifest data, so its wording is the pack's:
- **Descent:** floors 1 to the run's last floor (`resolveLastFloor`, the same rule the stairs use), labeled from `atlas.tileZoneBands`; a zone's name shows once the deepest floor reached gets there. The deepest floor is the larger of the engine's session count (`gameState.deepestFloor`, not saved) and the world counter a pack names in `deepestFloorCounter`.
- **Saga:** the current `objectives` entry; achieved `trackedMilestones`; then up to six locked ones, each shown as its `riddle` (or "? ? ?" without one), the rest counted as untold. A milestone with a `riddleAfterFlag` is counted as untold until that flag is set, so a beat the game reveals later (cotw: the two Níðhögg endings, after Víðnir speaks) is not given away from turn 1. A milestone achieved since the tab was last seen glows once.
- **Lore:** `loreEntries` (`LoreEntryDefinition`: `flag`, `title`, `verse`, `lore`, and an optional `fusionSpellId` the Spellbook's Fusions card counts as known once read) show once their flag is set, under `branding.loreTitle`, each verse and lore labelled by `branding.loreVerseLabel` and `loreNoteLabel` (cotw: Saga, Rune-lore). Like `trackedMilestones` they are a display list over existing flags, so the save format does not change.
- **Standing:** `worldState.factions`, named and gated by `factions` (`FactionDefinition`): a faction appears once its standing moves from its `initialWorldState` value, once its `metFlag` is set, or from the start with `metAtStart`; the rest stay unnamed.
Sealed pacts and their combined rewards are shown on the Pacts tab only, not repeated here.

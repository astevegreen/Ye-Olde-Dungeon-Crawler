# Monster

A monster is a `MonsterDefinition` (`src/engine/bestiary/monsterDefinitions.ts`) in one of the files under `src/content/cotw/monsters/`, which `monsters/index.ts` gathers into `COTW_MONSTERS`. Model: `1c5e9f8` (three set-piece monsters for the night raid), with the play-testing fixes `ef8810f` and `a8e3d23`.

## Steps
1. **Pick the file.** Done when the id is unique across `COTW_MONSTERS` and clashes with nothing under `src/engine/`, `src/ui/`, `src/rendering/` or `src/main.ts` (grep `'<id>'`): ids like `troll`, `hound`, `spider` or `giant` are sprite keys there, and fail the creep gate.
   - The seven zone files and `bosses.ts` are the pinned 37-monster roster (five a zone, two bosses). Add there only when the owner changes the roster, and then update `monsterRoster.test.ts` and the 37 in `monsters/index.ts`.
   - A set piece (a miniboss, a guard) goes in `minibosses.ts`, a prologue monster in `monsters/prologue.ts`; neither is count-pinned.
   - `legacy.ts` is the classic roster, a `Record` whose key must equal the `id`; it fills every wandering band.
   - A new file needs its import, an `export *` and a spread in `monsters/index.ts`.
2. **Write the definition.** Required: `id`, `name`, `stats` {hp, maxHp (equal), attack, defense}, `speed`, `aiType` (`melee`, `caster`, `coward`, `brute`, `immobile_turret`, or a pack strategy registered in `index.ts`), `fleeHealthPercent`, `xpValue`, `lootTable`. Every cotw monster also sets `minFloor`, nearly all set `tags` and `resistances`; the kill rite goes in `killRites.ts`, never inline.
   - **Tags** are declared, never inferred from the id, and they are gameplay as well as art: `boss` and `miniboss` change naming, and lift the monster's stats to at least its depth tier times `bossPowerFloorMultiplier` (`monsterScaling.ts`: 1.15 easy, 1.3 medium, 1.5 hard). A miniboss written at its neighbours' numbers fights well above them.
   - **Numbers** come from the monsters that unlock on the same floor. Then measure it there: the raid's first numbers dealt 1 damage against defense 8 and levelled the hero mid-raid. A throwaway script in `.prompts/` does it: a hero from `ProfileManager.createCharacter` levelled with `gainXp`, the monster from `createScaledMonster(def, id, pos, floor, undefined, undefined, cotwManifest.monsterScaling, difficulty)` added with `engine.addEntity` (as `turret.test.ts` does), then `MeleeAttackAction` both ways over a few seeds.
   - Every element in `resistances` must be in `COTW_AFFINITY_MATRIX` (`elements.ts`), or the resistance does nothing.
3. **Decide how it is met.** Done when you can name the floors where a run meets it.
   - **Drawn at random** (the default): floor population, vault guards and wanderers all draw from the whole catalog, weighted 1 on `minFloor`, ½ six floors later, about 0.1 twelve floors later. Its stats scale with depth, and from `minFloor + 10` it is named "Grim …". A monster unlocking alone on a floor takes a large share of that floor (the Warden filled 12–17 of floor 25's monsters), and `spawner.test.ts` fails one over 25% of draws on floors 5–49.
   - **Wandering:** list it in a band's `monsterIds` in `quest.ts`'s `floorEncounters`; an unknown id there is dropped without a word.
   - **A set piece:** `placedOnly: true`, with a comment naming its placement, as `minibosses.ts` does. Place it as a vault's `minibossId` or `preferredMonsters` (`VAULT.md`), a lair guard (`quest.ts`) or a prologue monster. A `placedOnly` monster with no placement is never met. A `boss` tag requires `placedOnly`.
   - A randomly drawn monster changes every seeded floor from its `minFloor` down; a `placedOnly` one changes none.
4. **Loot.** Every rule's `generate` uses the `rng` it is given. `itemDrop(weight, itemId)` (`items/makeItem.ts`) for ordinary drops: its chance is the weight times the pack's drop scale, and it drops nothing shallower than the item's `minFloor`. `coinDrop(richness)` (`coinage.ts`) for coin, 1 being ordinary for the depth. `makeLootItem` for a guaranteed drop; a miniboss fixes its floor at the shallowest one it is met on, `(id, rng) => makeLootItem(x, id, rng, 36)`, since a test calls `generate` with no floor. The item must be in `COTW_ITEMS`; an unknown id throws when the pack loads.
5. **Kill rite.** An entry keyed by the id in `COTW_KILL_RITES` (`killRites.ts`), in its zone's section, with `hintVerse` and `essenceElement`; `monsters/index.ts` attaches it. Every monster has one except those `COTW_PROLOGUE.monsters` places, which must have none: they leave before a rite could be met. The rite must be meetable within ten floors of `minFloor` (a rite that teaches a spell, on `minFloor` itself), never asks for a status the monster is immune to, and an overkill rite never asks more than the element's strongest spell deals after resistance.
6. **Bestiary family.** Add the id to exactly one family's `members` in `monsterCategories.ts`. A bigger family reaches mastery sooner; its `masteryKills` were measured (`faa05ab`).

## Finish
- **Tests:** the content suite already loops over every monster (roster schema, rites, family, sprite keys, matrix elements, spawn shares, loot volume, vault guards). Add a test of anything new the monster does: a hook, an AI, a placement (generate the floor and find it).
- **Sprite:** a recipe keyed by the definition id in `COTW_MONSTER_SPRITES` (`sprites/monsters.ts`, colours from `COTW_ATLAS_THEME.palette`) wins. Without one, the pack's `atlas.spriteTagRules`, then the generic tag order (`boss`/`miniboss` draw as `giant_boss`), then name guesses, then `kobold`: most cotw monsters draw from tags, so pick tags that look right. An alias in `sprites/index.ts` also joins `aliases` in `spriteRecipes.test.ts`.
- **Creep:** monster ids are collected (names and tags are not). Rename on a clash; the allowlist already holds `kobold`, `skeleton`, `giant_rat`, `orc`, `wolf`, `ogre` and `goblin`, and removing one of those monsters means deleting its entry.
- **Gates:** `npx vitest run src/content/cotw/__tests__` while iterating, then `npm run gate-stamp -- run lint test` and `npm run sim`. A randomly drawn monster changes the floor mix: run `npm run balance` before and after, and quote both.

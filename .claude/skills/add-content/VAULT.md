# Vault

A vault is a `VaultBlueprint` (`src/engine/dungeon/vaultStamp.ts`): a hand-drawn room the floor generator stamps into a floor. Models: `b248acf` (the smallest: one vault, its miniboss, one test), `bc32c0e` (a forge vault guarded by a `placedOnly` miniboss), `2d03340` (four scripted vaults with tiles and choices; `26fa781` fixed what its tests missed).

## Steps
1. **Pick how it is placed.** Done when you can name its floors and the field that puts it there.
   - **Random:** leave `scriptedOnly` unset. Each floor draws one or two vaults, uniformly, from those whose `minFloor`/`maxFloor` admit it; there are no weights. Floors 10–17 take no random vaults (`randomVaults: false`, `floorLayouts.ts`), nor does the lair.
   - **Landmark:** add the id to a band's `landmarkVaultIds` (`floorLayouts.ts`). A landmark stamps once a floor across its band and ignores `minFloor`/`maxFloor`, so the band itself must start no shallower than the vault belongs. Set `scriptedOnly: true` too, or the random draw also stamps it elsewhere.
   - **Scripted:** one forced vault per floor, the first placement that names the floor, and a rune vault takes its floor first. Floors taken today: 5, 13, 21, 22, 25, 30, 32, 36, 37, 39, 42, 45, 47, 49 (`scriptedVaultPlacements` in `index.ts` and the rune floors); pick another. Set `scriptedOnly: true` and both `minFloor` and `maxFloor` to the floor.
2. **Draw the blueprint** and append it to `COTW_VAULTS` (`vaults.ts`); export `<NAME>_VAULT_ID`/`_FLOOR` constants at the top only when `index.ts` or a test imports them (knip fails an export nothing imports). Required: `id`, `name`, `description`, `minFloor`, `layout`. Optional: `maxFloor`, `preferredMonsters`, `minibossId`, `legend`, `scriptedOnly`; `predicate` is never read.
   - **Symbols:** `#` wall, `~` shallow water, `X` chasm, `+` closed door, `B` iron bars, `P` pillar, `@` connector, `C` chest, `M` guard, `K` miniboss (from `minibossId`, starts hunting), `N` an NPC's spot (forced vault only). Any other character is floor.
   - **Geometry:** rows of equal width; `@` only on the outer edge, since the corridor carves outward from it; stay near the existing 15×10. Every `C` must be reachable from an `@` with doors open and bars and chasm closed, or the floor redraws until it falls back to rooms and corridors.
   - **Legend:** maps a character to a pack tile type and wins over the built-ins, but only for a registered tile: an unknown one silently becomes floor or the built-in, and the reachability checks treat every legend cell as walkable.
3. **Guards.** `M` draws uniformly from `preferredMonsters`; a guard whose spawn weight on that floor is under 0.1 is swapped for the floor's own monsters. That weight counts a floor shallower than the guard's `minFloor` as weight 1, so a guard stands there anyway: list only monsters that belong at the vault's shallowest floor. A miniboss lives in `monsters/minibosses.ts` with `placedOnly: true`, the only thing keeping it out of random spawns, and is met only through a vault (follow `MONSTER.md` for it). Vault interiors get no room monsters, traps, spawn point or stairs.
4. **Pack tiles** for legend characters: a `TileDefinition` in `COTW_TILES` (`tiles.ts`). An interactive tile sets `interactionHandlerId` to a `COTW_CHOICES` key, plus `landmarkLabel` and `glyph`; `visual: 'altar' | 'portal'` draws a fixture overlay. Models: the Siphon Altar and the grotto veil. A choice on the tile follows `STORY.md`.
5. **Scripted placement:** import the constants into `index.ts` and add `{ floor, vaultId, npcs? }` to `scriptedVaultPlacements`. NPCs fill the `N` spots in reading order (extras on either side are dropped), stand still, default to `villager`, and their `choiceId` must be a `choices` key.

## Finish
- **Tests:** every vault in `COTW_VAULTS` is already checked for a connector, chests reachable in the blueprint, guard and miniboss ids that exist, and scripted floors unique. `layoutStrategies.test.ts` generates 60 seeds only for its fixed `CASES` floors, so a new vault is played there only if one of those floors admits it, and then only when drawn. Three past vaults passed the blueprint checks and still broke on a real floor, so every new vault gets a generation test like `zoneLayouts.test.ts`'s: present and reachable from the stairs, generated with `engine.registries` when it has legend tiles. A scripted or landmark vault is present on every seed (15 is enough); a random one shows on roughly 12–41% of a floor's seeds, so sweep about 100 and assert it appears. Assert its legend's tile ids exist (no test does).
- **Two set pieces on one floor:** a random vault whose range spans 5 can stamp beside the forced rune vault and Gálmr, so floor 5 holds two minibosses (the trial vault did on 25 of 200 seeds). Name the overlap to the owner, or start the range at 6.
- **Sprite:** a pack tile with no recipe draws as the zone's floor. Its art is a `<tileType>~prop` (or `<tileType>_<zone>~prop`) recipe in `COTW_TILE_SPRITES` (`sprites/tiles.ts`), glow in the zone's `emissive` map (`terrain/index.ts`); `spriteRecipes.test.ts` fails on a key another group already uses.
- **Creep:** vault ids and scripted `vaultId`s are collected; legend tile ids are not. A new vault needs no allowlist entry.
- **Gates:** `npx vitest run src/content/cotw/__tests__ src/engine/dungeon` while iterating, then `npm run gate-stamp -- run lint test`. `npm run balance -- --floors N` counts its guards and chests through real generation; `npm run sim` reaches only floors 1–6.

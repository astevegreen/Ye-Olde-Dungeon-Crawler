# Automated Quality Gates

> What each gate checks, and why it is shaped so; [`ARCHITECTURE.md`](../../ARCHITECTURE.md) §7.2 holds the rules and wins any disagreement, and the scripts win over this file (flag it, §8.2). Run counts and timings are whatever the latest output says.

## Where the Gates Run
- **`npm run gates`:** lint, both test gates, sim, schema, build, then Playwright (Chromium), stopping at the first failure, and stamps lint and the tests. Without it, a presentation change would first meet Playwright at the push.
- **CI:** `deploy.yml` is the gate on `main`: every push runs lint, tests, sim, schema and build, beside `playwright.yml` (called as a job), then deploys `dist/` to GitHub Pages only when both pass, so a build that fails in a Linux browser never reaches players. `ci.yml` and `playwright.yml` run the same on pull requests only, and nearly all work reaches `main` by a direct push.
  - **A push that ships nothing runs the gates only** (`scripts/deploy-scope.mjs`, its rule in `scripts/lib/deploy-scope.mjs`): when every file it changed is docs, instructions, tooling, Vitest suites and fixtures, the soak or the relay, the browser runs and the deploy are skipped, since the site would be rebuilt the same; 29 of 40 deploys before 28 Oct were such pushes. Any other file, a push whose files can't be listed (a new branch, a force-push) and a manual run deploy as before.
  - Only the branch tip deploys: browser runs finish out of order, and an older push finishing last would otherwise replace a newer one. `npm run ci:watch` (`scripts/watch-ci.ts`) waits for a pushed commit's run, names a failed step and says whether it deployed; CI runs on Linux, where a test can fail that passes on Windows.
  - **The required checks gate pull requests only** (GitHub branch protection): a pull request merges once `gates` (`ci.yml`) and `test` (`playwright.yml`) pass. Cloud sessions run no repo hooks, so their work reaches `main` through a pull request and these checks are its gate. Admins are exempt, and every direct push to `main` is an admin's, so it lands without them and prints `Bypassed rule violations … 2 of 2 required status checks are expected`; for those pushes the pre-push hook and `deploy.yml` are the gate. SonarCloud stays advisory. `npm run sonar -- <pr>` (`scripts/sonar.ts`) reads its findings from the check run it posts to the pull request: GitHub serves the run's annotations to anyone who can read the repo, so no SonarCloud token is involved, and the fixed, read-only command needs one allow rule instead of a prompt per ad-hoc `gh api` loop. SonarCloud sends GitHub about 50 findings per analysis; the script says when its "New issues" count is higher. The project's open backlog on `main` is `npm run sonar:issues` (`scripts/sonar-issues.ts`): anonymous GETs of SonarCloud's public `api/issues/search` for the one project key, BLOCKER and CRITICAL by default, or any severity in `-- --files <path>...`, at most 50 lines. No token is read or sent; if the project turns private (401, 403 or 404) it fails and says so.
- **Local pre-commit hook:** `.githooks/pre-commit` runs lint, the unit tests and, when the tooling changed, the tooling tests. `npm install` wires the hooks (`prepare` sets `core.hooksPath`); `SKIP_HOOKS=1` bypasses any of them, on the owner's say-so only (§8.4).
  - **Gate stamps** (`scripts/gate-stamp.ts`): the hook skips a gate that already passed on this exact tree; a third of hooked commits had rerun both on a tree where they had just passed. A stamp lives in `.git/gate-stamps/<hash>.json` (per clone, newest 40 kept); the hash covers every tracked and untracked, not-ignored file's content plus the Node version, so any edit, addition or deletion misses (staging a deletion for the commit does not).
  - **A stamp caches a pass; it is never an authority.** A tree that can't be fingerprinted runs every gate; a stamp is written only for a pass on a tree byte-identical before and after. `npm run gate-stamp -- run lint test tooling` and `npm run gates` write stamps; a bare `npm run lint` or `npm test` writes none, since a filtered run proves nothing about the tree. `GATE_STAMP=off` ignores stamps. The slow gates are never stamped.
  - **The tooling tests run when the tooling changes:** nine tests spawn processes to try the repo's own tooling (the gate scripts, gate stamps, handoff notes, the commit-msg hook, the deploy scope and the pre-push hook's sprint lock: the `tooling` project in `vite.config.ts`), 15 of the suite's 22 s for code most commits never touch. Their gate is stamped on the tooling's files alone (`paths` in `scripts/gate-stamp.ts`), so pre-commit skips it until one changes. The pre-push hook and CI run them on every push, since a game change can break one too (the engine-creep test plants a real spell id).
- **Local pre-push hook:** the tooling tests, sim, schema, build and Playwright in all three browsers (`PW_ALL_BROWSERS=1`). Commits go straight to `main`, `ci.yml` runs only on pull requests and `deploy.yml` after the push, so without it the slow gates would first run after the code landed.
  - **One Playwright retry** (`--retries=1`; CI has two): known flakes failed two pushes in a row on 9 Oct, and a test that passes on retry is reported as flaky instead of blocking. A test that fails twice still blocks.
  - **A push that updates only the `handoffs` branch runs no gate.** That orphan branch holds handoff notes (`.claude/skills/handoff/notes.mjs`), never merges and deploys nothing; a note push had run the full Playwright suite for a markdown file.
  - **The sprint lock runs first:** while this computer's sprint window is open (`sprint-window.json` in the shared git folder, [sprint.md](../sprint.md)), a push to `main` from any folder but the integrator's worktree is refused (`scripts/sprint/push-lock.mjs`), so lane work lands only through the integrator. The sprint guard refuses a lane session's push before it runs; the lock also stops one from the owner's terminal or a session without the guard. `SKIP_HOOKS` skips the gates after it, never the lock; `/sprint-stop` ends the window. A window file that can't be read refuses, since a sprint may be running.
- **Local commit-msg hook:** rejects a commit staging a protected file unless the message names `§8.1 exception N` (on `engine.ts` and `actionPipeline.ts`, exceptions 4 and 5 need the change or reason on their line, and the hook reminds that the push waits for the reviewer's PASS and a second-look `ship`; exception 5 never covers `migrator.ts`), and rejects an `Agent: Antigravity` line (§8.4). It warns, never blocks, on a large commit spanning several areas.
- **Second look and rail audit** (`scripts/second-look.mjs`, run before a push, CLAUDE.md Pushing): another model reviews the commits through agy and the script ends `Verdict: ship|fix|owner|retry`. A `[blocker]` holds the push (`fix`); notes never do. A change touching a rail (`RAILS` in `scripts/lib/second-look.mjs`: Claude Code hooks and settings, the sprint guard and the skills and agents that wire it, git hooks, CI, the gates with their allowlists and configs, the review itself, the deploy's scope, the sprint queue and push lock) first gets a deep audit with one question, whether it loosens a check; `yes` holds it for the owner (`owner`), and no answer at all (`retry`) keeps it unpushed rather than unaudited. A loosened gate hides its own failure, so this audit stands where an owner's review of rail changes used to.
- **Line endings:** `.gitattributes` pins LF in the repository and the working tree whatever `core.autocrlf` says, and names `.githooks/**` and `*.sh` explicitly: a CRLF `#!/bin/sh` line breaks the hook, and a mixed tree once made scripts matching `"\n"` silently miss files.

## Playwright
The suite plays the built `dist/index.html` over `file://`. A local run is Chromium only; `CI` or `PW_ALL_BROWSERS` adds Firefox and WebKit, since browser-specific breakage is rarer than logic breakage. Workers are a quarter of the logical cores: at half, Firefox timed out. Specs that start a hero call `e2e/newHero.ts`'s `pastTheOpening`, which ends the opening through the F2 triage API.
- **A game error fails its test:** specs import `test` and `expect` from `e2e/fixtures.ts`, whose automatic fixture fails a test on an uncaught exception, a `console.error`, or an error the engine caught and played on past (§4, read through `engine.diagnostics.recordedErrors()`); a spec once had to remember its own `pageerror` listener, and none watched the other two. A test that causes one on purpose calls `gameErrors.allow(/…/)`. The soak keeps its own listeners, since it reports errors as findings.
- **Gate specs:** `smoke`, `gameplay` (moving, saving, HUD layout, modal focus, the mouse), `story-milestones` (Chromium; the runestone and Víðnir choices on real floors and their flags across a save, the mana orb, a melee hit's floating text), `feedback-and-diagnostics` (F2/F3), `whole-run` (Chromium; three runs to their endings, scenes set by the triage API) and `prologue` (Chromium).
- **Opt-in**, outside every gate (`testIgnore`): `gameplay-record` (`npm run test:record`, a video) and `soak` (`SOAK=1`; the `soak` skill, `.claude/skills/soak/SKILL.md`, runs and reads it).

## Static Gates
Each static gate fails when it inspects no files, so a wrong working directory never passes silently. No test writes into `src/`: suites walk it in parallel, and a file deleted mid-walk fails them. A gate's regression test plants its violation in a temp directory and passes `--overlay <tree-path>=<file>` (`scripts/lib/gate-overlays.ts`), which scans the file as though it sat at that path.

### 1. Architectural Purity & Boundaries
`npm run check:engine-purity` (`scripts/check-engine-purity.ts`) scans `src/engine/`, `src/content/`, `src/ui/` and `src/rendering/`.
- **Simulation purity (§2):** engine and content source (tests exempt) names no DOM, browser, timing or audio global (the script lists them), whether or not it registers hooks.
- **Imports (§3):** an import is any specifier a file names (`import`, `export … from`, side-effect, dynamic or type-position `import()`, `require`); a specifier computed at run time is invisible. The engine imports no presentation, and its production source no content; content imports no presentation and no engine deep path; presentation, `src/main.ts` and `src/main/**` import the engine only through its index, and only `src/main.ts` may import a pack. Content tests may deep-import the engine; presentation tests may not, so they meet the same gaps in the index that presentation code would. `purityGatePatterns.test.ts` and `mainScopeGateWidening.test.ts` plant each form.
- **Randomness and the clock (§7.2):** fails on `Math.random`, `crypto` randomness, `Date.now()` and an argument-less `new Date()` in engine and content source. Presentation may jitter particles (`fxRunner.ts`). A `// purity-allow: <reason>` pragma marks an entropy-boundary line; timestamps are allowlisted per file in `scripts/purity-clock-allowlist.json`.

**Engine encapsulation** (`npm run check:engine-encapsulation`): the type checker matches a write by the class declaring the member, not by variable name.
- In presentation, `src/main/**` and content (tests exempt): no assignment, `++`/`--`, `delete` or index write to an engine class member, including through a cast or a local alias the cast initialises, and no `Object.assign`, `Reflect.set` or `Object.defineProperty` onto one; no write into a plain object reached through an engine member (`NESTED_WRITE`).
- In presentation only: no call into an internal subsystem (`GameMap`, `Container`, `StatusManager`, …) unless its name reads as a query (`get`, `is`, `has`, `find`, …). Deny by default: a list of mutator verbs missed `consolidateCoins` and `triggerDeath`.
- Sanctioned writes carry reasons in `scripts/engine-encapsulation-allowlist.json`. Not traced: a write through a local alias of a member's value.

**Engine creep** (`npm run check:engine-creep`): loads every pack's `index.ts`, collects every id, NPC name, quest reference and `…flag` string it declares, and fails when engine production source or presentation names one as a literal, template segment, object key or, for an underscored id, inside a longer string. Presentation also fails on a `'<packId>:` prefix. Engine-enum vocabulary a pack restates is not collected; overlaps carry reasons in `scripts/engine-creep-allowlist.json`.

**UI palette ratchet** (`npm run check:ui-palette`): each presentation file's and `index.html`'s net color-literal count against `scripts/ui-palette-baseline.json`. A rise fails, and so does a fall until `-- --update` lowers the baseline, so it only turns down.

Every allowlist fails on a stale entry.

### 2. Determinism & PRNG Discipline
Outcomes and generated ids (`GameEngine.nextSimulationId`) draw from `engine.prng`, and `rng` parameters are required, never defaulted, so a seed replays exactly. The clock is read once per run, outside the simulation: `ProfileManager.createCharacter` seeds the run PRNG (`options.seed` when given) for the starting kit and the engine. Save timestamps and profile ids stay on the clock: seeded profile ids would collide for two heroes made from one seed.

### 3. Schema Evolution Integrity
`npm run validate:schema` (`scripts/validate-schema.ts`) passes a current-version save through unmigrated, checks a save below the floor is refused, and runs a probe `N -> N+1` step so the migration machinery stays exercised (§5). It round-trips a live engine through `serializeGame`, `JSON.stringify`/`parse` and `deserializeGame`, since saves persist as strings, and checks surfaces, ground items and PRNG state survive; PRNG states compare int32-normalized, plus the next draw. Per-step assertions live in `migrator.test.ts`.

### 4. Headless Simulation
`npm run sim` (`scripts/headless-sim.ts`) takes its populations from real generated cotw floors (several floors and seeds, base and pact-boosted densities), not a hard-coded count, then runs a dormant floor, an awake floor, a 1,000-cast Magic Arrow workload and a mixed one: every typed spell of the pack cast in turn among foes, where each summon must bring an ally. It fails on a rejected action or a cast that spends no turn, a caught pipeline exception, a broken actor invariant at its 100-turn checkpoints (a non-finite scalar, an actor out of bounds, a duplicate id), a deadlock (six successful player actions that don't advance the turn) or a median over its wall-clock budget; budgets live here, never in `npm test`. `--inject-error` shows the failure path. The long chaos simulation is `chaosSimulation.test.ts`, under `npm test`.

### 5. Static Analysis & Build
- **`npm test`:** every Vitest suite, its two projects being `npm run test:unit` and `npm run test:tooling`, including `docReferences.test.ts`: a cited `§N` or `P-NN` that doesn't exist, a `[Planned: P-NN]` with no §9 entry, a relative doc link to a missing file, and root markdown other than `ARCHITECTURE.md` and `CLAUDE.md` all fail.
  - **One module graph per worker** (`isolate: false`, half the wall time): a file puts back the process state it changes, and `tests/setup/sharedState.ts` fails one that leaves fixtures in the default registries. Spies and stubbed globals go back before each test on their own (`restoreMocks`, `unstubGlobals`), so one left by a failing test can't leak into the next. `npx vitest run --isolate` tells a leak from a real failure.
  - **Workers are capped at eight:** each worker builds its own module graph, and past about eight the extra graphs cost more than they save. A `.only` fails the run (`allowOnly: false`), so a stray one can't pass the gate on a fraction of the suite.
  - **An isolated failure fails its test** (§4): the engine catches an error at its boundaries and plays on, so a test whose action threw would still pass, and one did, its assertion swallowed inside a choice callback. `tests/setup/sharedState.ts` fails a test whose run recorded an error in the flight recorder unless the test called `allowIsolatedFailures()` (`tests/setup/isolatedFailures.ts`), as the failure-isolation tests do.
- **`npm run lint`:** `tsc` over the main include set, then over `e2e/` with its own tsconfig (Playwright strips types without checking them), then the `check:*` scripts above and `knip`. knip's entries are `src/main.ts`, the scripts, the relay and the tests, so an export nothing reaches fails, dead engine API included; `npx knip --production` lists exports only tests use, which should be deliberate seams (a pack validator the pack's tests run, a reset of process state, a type a presentation test imports); a helper only tests call lives in a test file or `src/engine/__fixtures__/testHelpers.ts`, not in shipping code. knip doesn't see unused class members.
- **`npm run build`:** `tsc && vite build`, the cotw single file, with no type errors or bundler warnings.
